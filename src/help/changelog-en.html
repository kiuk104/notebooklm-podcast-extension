Detailed changelog

Full commit history at GitHub commits. Below are user-visible changes only, newest first.

v0.4.40 (2026-05-13) — Help-page reorganization

  • Help §12 compressed to theme-grouped summary; per-version detail moved to this page. Lets users skim the big picture on the help page and jump here only when they need version-level detail.

v0.4.39 (2026-05-13) — Cross-device skip leak fix

  • Skipped cards being re-downloaded on a different device — fix for a race where a card's artifact-labels DOM hadn't rendered yet, leaving the shortId empty so the skip filter was bypassed. Added a (date, titleSlug) fallback match so the race case is now blocked correctly. The "Skipped" badge on the option-page tree is now consistent too.

v0.4.38 (2026-05-13) — Faster all-notebook scan

  • Auto-reuse the last scan result — clicking [Scan all notebooks] again within 30 minutes returns instantly without re-scanning. Cuts the wait to near-zero when you re-confirm after an auto-download. Shift+click for a forced full scan.
  • Per-notebook change detection cache — extracts absolute timestamps / count signals from the home-page notebook cards to build a "structural fingerprint". Notebooks scanned within 4 hours are skipped (no tab opened) if their fingerprint is unchanged. Adding a new audio overview etc. changes the fingerprint and triggers a full scan automatically.
  • Graceful degrade — if NotebookLM's DOM does not expose those signals, every notebook is scanned in full (same as before). The extraction rate is visible in the SW console as [scan:list].

v0.4.37 (2026-05-13) — Bulk download stability

  • UI freeze fixed — popup / options page no longer pauses 1-2 seconds per large card (40MB m4a). Synchronous base64 encoding moved fully into the offscreen document, off the service worker thread.
  • Bulk popup window hidden — the NotebookLM popup no longer pops in front of whatever you're browsing. Now created at off-screen coordinates (-32000, -32000). Download behavior unchanged.
  • Live per-card progress — the progress monitor shows the current card's stage (download / transcode / upload) and byte progress bar. Previously only start/end events were visible.
  • Fast recovery from stalled cards — a stuck card now moves on after 90 s of zero progress, instead of the old fixed 10-minute timeout. Normal cards stay alive because each fetch chunk emits an activity signal.

v0.4.36 (2026-05-12)

  • Auto-remove local download after a successful GitHub push (default ON) — the m4a/mp4 in your Chrome Downloads folder is cleaned up after push. Since GitHub now holds the mp3, the local copy is redundant disk use. Failed pushes are kept (retry-able). Toggleable in the GitHub settings page.

v0.4.35 (2026-05-12)

  • Edit retention cap from the metadata page — retention.maxTotalMB in docs/podcast.json can now be changed from the extension UI. Default 2000. Usage panel refreshes immediately on save.

v0.4.34 (2026-05-11)

  • [Clean up over-limit] button — in the usage panel (Progress Monitor + Episodes List), the extension itself deletes the oldest files past the retention cap and registers them in the permanent skip list. Same result as the workflow's retention cut, but also writes to the skip list so the next scan won't re-flag them as new.
  • Bulk [Skip] action — episodes toolbar gets a blue [Bulk skip] next to [Bulk delete]. Select multiple via checkboxes and delete + register them in one go.

v0.4.33 (2026-05-10)

  • [Skip] now = delete + permanent block — [Delete] only removes the file (may be re-downloaded on next scan); [Skip] deletes and registers in the permanent skip list (frees space + future-proof block).
  • Skip list keeps metadata — filename / title / notebook name / date / registered-at saved with each entry. The [Skip list] toggle panel shows what each entry was.
  • Older v0.4.32 skip entries (shortId only) are auto-migrated.

v0.4.32 (2026-05-10)

  • Permanent re-download loop avoided — fixes the structural issue where bulk push → workflow cuts via retention → next scan re-flags the same card as new → infinite download.
  • Auto-skip old cards (default 730 days) — input in the GitHub settings page. Notebook cards older than N days are skipped from bulk downloads from the start.
  • Storage usage panel — Progress Monitor + Episodes List both show usage / cap / % bar (75% yellow, 90% red).
  • Skip-list management — persisted in chrome.storage.sync (multi-device). Episode rows get a [Skip] action; [Skip list] toggle lets you unset individual entries or clear all.

v0.4.31 (2026-05-10)

  • artifact-labels race fix — scans no longer return before NotebookLM's <span id="artifact-labels-{UUID}"> renders. content.js scan handler polls up to 3 seconds for dedup keys to populate.
  • workflow push retry — when the extension's ghPut races with the workflow's git push, the workflow now resets to origin/main, rebuilds, and retries up to 3× with backoff.
  • 4-segment titleKey fallback — dedup recovers via (date, titleSlug, ext) even when artifactId is empty due to the race.

v0.4.30 (2026-05-10)

  • Multi-device sync via Chrome Sync — GitHub settings (PAT included) + UI language move to chrome.storage.sync. Automatically shared with the same extension on other Chromes signed into the same Google account.
  • Picker mode (cross-notebook card picker) — [Pick cards ▾] opens per-notebook tree; checkboxes per card for partial downloads.
  • Dedup gap fixes — older 3-segment files (pre-v0.4.0) now also matched by (date, title, ext). cover.title race fixed.
