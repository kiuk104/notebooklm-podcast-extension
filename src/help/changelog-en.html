Detailed changelog

Full commit history at GitHub commits. Below are user-visible changes only, newest first.

v0.4.49 (2026-06-15) — Fix skipped cards reappearing after the skip list was silently truncated

  • Fixes skipped cards being re-flagged as "new" and repeatedly retried/failing in bulk downloads. The skip list was stored in a single chrome.storage.sync item (8KB per-item limit) together with metadata, so entries (Korean titles, etc.) grew large and once you passed ~40 skips the oldest ones were silently trimmed. A trimmed skip reappears as new on the next scan → gets retried → (if you deleted the card in NotebookLM) fails → is auto-skipped again → exceeds the quota again and evicts another skip → endless churn. The skip data now lives in unlimited local storage (tens of thousands of entries kept, no truncation); only compact identifiers are mirrored to sync for cross-device. Your existing skip list migrates automatically.

v0.4.48 (2026-06-15) — Exclude Featured notebooks from scan / auto-recovery for missed feed rebuilds

  • Google "Featured notebooks" are no longer swept into the scan. NotebookLM's home page lists a "Featured notebooks" section (Google-provided sample/shared notebooks) alongside your own. These were being scanned and flagged as new. Now only your "Recent notebooks" are scanned and downloaded; the Featured section is skipped. This also resolves the side effect where those cards — often grabbed before their cover/identifier finished loading — kept reappearing as new even after you skipped them.
  • Fixes episodes that uploaded but never made it into the RSS feed (feed.xml). The feed rebuild that runs right after a download could be dropped if the Service Worker shut down or GitHub returned a transient error — leaving the episode saved on GitHub but absent from the RSS feed, so it never showed up in podcast apps (YouTube Music, etc.) until a later download happened to succeed. Now the extension (1) retries a failed feed rebuild, (2) reconciles the feed against the episode list whenever a bulk download or full scan finishes, and (3) re-checks on startup, rebuilding automatically when they diverge.

v0.4.47 (2026-06-04) — Skipped-card retry loop fix / back-to-top / two report channels

  • Fixed skipped cards failing forever in bulk download — if a card you had skipped was later deleted in NotebookLM, some paths ("Retry N failed", manual pick-and-download) bypassed the skip filter and kept re-attempting it → "card not found" every time → permanently piling up in the failed list. Now every download path runs the skip list first. Additionally, when a card is confirmed deleted from NotebookLM mid-download, it is auto-registered as skipped so it won't be picked up again on the next scan/retry.
  • More accurate "N new" count — the last-scan summary no longer miscounts skipped cards as "new". Skipped cards are shown separately as "N skipped".
  • Added [↑ Back to top] button to the episode list — for long lists, jump from the bottom of the table back to the top of the page with a smooth scroll.
  • Split "Report issue / suggestion" into GitHub issue + email — in the popup, options sidebar, and help footer you can now choose between 🐛 Open a GitHub issue and ✉️ Send an email. The email subject is pre-filled with the current version.

v0.4.46 (2026-05-21) — Bulk-skip selected cards

  • Admin page "Latest scan results → Select cards" tree now has a [Skip selected] button — adds all checked cards to the permanent skip list in one click. They will no longer appear as new in future scans. Useful when the skip list was wiped (reloading the extension from a different path) or to block a batch of unwanted cards at once. Skipped cards disappear from the tree immediately after registration.

v0.4.45 (2026-05-21) — Fix bulk download screen-transition glitch

  • Fixed the popup window briefly flashing in front of your screen at every notebook during bulk download — Chrome's behavior on Windows changed so that chrome.windows.create({focused:false}) is no longer honored, and every chrome.tabs.create({active:true}) raised the popup to OS foreground. Refactored to reuse a single tab across notebooks by navigating via chrome.tabs.update — tabs.create is never called during a bulk session. Screen-transition events drop from N (one per notebook) to at most 1 (first windows.create only).
  • debugger.attach also happens only once per session — the yellow debugging banner raise is now a single occurrence.

v0.4.43 (2026-05-20) — View by feed order toggle

  • "View by feed order" toggle — shows the episode list in the current saved feed order without entering edit mode. When toggled on, reads the episodeOrder array from podcast.json on GitHub and sorts the list accordingly (files not in the array appear at the end, newest-first). Group, sort, and edit-mode buttons are disabled while the view is active.

v0.4.42 (2026-05-20) — Download window fix + feed order editing

  • Bulk-download popup window coordinates fixed — Chrome's May 2026 update added a requirement that ≥50% of a window's area must fall within the visible screen. The previous left:-32000, top:-32000 coordinates were rejected with an error, causing every bulk download to fail with "tab open failed". Fixed by changing to left:-399, top:0, width:800, height:600 (visible width 401px = 50.1% of the window). focused:false and visibilityState='visible' behavior preserved.
  • Episode RSS feed order editing — the episodes section on the admin page gains an [Edit feed order] button. Drag rows via the ☰ handle or use ▲▼ buttons to reorder. [Apply to feed] saves the order as the episodeOrder array in docs/podcast.json and immediately rebuilds feed.xml (extension-direct RSS mode). [Reset to default order] removes custom ordering (reverts to newest-first).

v0.4.41 (2026-05-20) — Help pages update

  • Added §6-6 (feed order editing) and §6-7 (view by feed order) to all help pages. Updated §3-3 download window description. Added v0.4.42 theme to §12.

v0.4.40 (2026-05-13) — Help-page reorganization

  • Help §12 compressed to theme-grouped summary; per-version detail moved to this page. Lets users skim the big picture on the help page and jump here only when they need version-level detail.

v0.4.39 (2026-05-13) — Cross-device skip leak fix

  • Skipped cards being re-downloaded on a different device — fix for a race where a card's artifact-labels DOM hadn't rendered yet, leaving the shortId empty so the skip filter was bypassed. Added a (date, titleSlug) fallback match so the race case is now blocked correctly. The "Skipped" badge on the option-page tree is now consistent too.

v0.4.38 (2026-05-13) — Faster all-notebook scan

  • Auto-reuse the last scan result — clicking [Scan all notebooks] again within 30 minutes returns instantly without re-scanning. Cuts the wait to near-zero when you re-confirm after an auto-download. Shift+click for a forced full scan.
  • Per-notebook change detection cache — extracts absolute timestamps / count signals from the home-page notebook cards to build a "structural fingerprint". Notebooks scanned within 4 hours are skipped (no tab opened) if their fingerprint is unchanged. Adding a new audio overview etc. changes the fingerprint and triggers a full scan automatically.
  • Graceful degrade — if NotebookLM's DOM does not expose those signals, every notebook is scanned in full (same as before). The extraction rate is visible in the SW console as [scan:list].

v0.4.37 (2026-05-13) — Bulk download stability

  • UI freeze fixed — popup / options page no longer pauses 1-2 seconds per large card (40MB m4a). Synchronous base64 encoding moved fully into the offscreen document, off the service worker thread.
  • Bulk popup window hidden — the NotebookLM popup no longer pops in front of whatever you're browsing. Initially used off-screen coordinates (-32000, -32000); updated in v0.4.42 to left:-399, top:0 due to Chrome's new 50% visibility rule. Download behavior unchanged.
  • Live per-card progress — the progress monitor shows the current card's stage (download / transcode / upload) and byte progress bar. Previously only start/end events were visible.
  • Fast recovery from stalled cards — a stuck card now moves on after 90 s of zero progress, instead of the old fixed 10-minute timeout. Normal cards stay alive because each fetch chunk emits an activity signal.

v0.4.36 (2026-05-12)

  • Auto-remove local download after a successful GitHub push (default ON) — the m4a/mp4 in your Chrome Downloads folder is cleaned up after push. Since GitHub now holds the mp3, the local copy is redundant disk use. Failed pushes are kept (retry-able). Toggleable in the GitHub settings page.

v0.4.35 (2026-05-12)

  • Edit retention cap from the metadata page — retention.maxTotalMB in docs/podcast.json can now be changed from the extension UI. Default 2000. Usage panel refreshes immediately on save.

v0.4.34 (2026-05-11)

  • [Clean up over-limit] button — in the usage panel (Progress Monitor + Episodes List), the extension itself deletes the oldest files past the retention cap and registers them in the permanent skip list. Same result as the workflow's retention cut, but also writes to the skip list so the next scan won't re-flag them as new.
  • Bulk [Skip] action — episodes toolbar gets a blue [Bulk skip] next to [Bulk delete]. Select multiple via checkboxes and delete + register them in one go.

v0.4.33 (2026-05-10)

  • Skip list keeps metadata — filename / title / notebook name / date / registered-at saved with each entry. The [Skip list] toggle panel shows what each entry was.
  • Older v0.4.32 skip entries (shortId only) are auto-migrated.

v0.4.32 (2026-05-10)

  • Permanent re-download loop avoided — fixes the structural issue where bulk push → workflow cuts via retention → next scan re-flags the same card as new → infinite download.
  • Auto-skip old cards (default 730 days) — input in the GitHub settings page. Notebook cards older than N days are skipped from bulk downloads from the start.
  • Storage usage panel — Progress Monitor + Episodes List both show usage / cap / % bar (75% yellow, 90% red).
  • Skip-list management — persisted in chrome.storage.sync (multi-device). Episode rows get a [Skip] action; [Skip list] toggle lets you unset individual entries or clear all.

v0.4.31 (2026-05-10)
