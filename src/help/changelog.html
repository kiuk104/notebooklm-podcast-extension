버전별 변경사항 (상세)

전체 commit 히스토리는 GitHub commits 참고. 아래는 사용자 입장에서 체감되는 변경만, 최신 버전부터.

v0.4.46 (2026-05-21) — 선택 카드 일괄 스킵 버튼

  • 관리 페이지의 "직전 스캔 결과 → 선택해서 받기" 트리에 [선택 카드 스킵] 버튼 추가 — 체크한 카드들을 한 번에 영구 스킵 목록에 등록. 다음 스캔부터 신규로 잡히지 않음. 익스텐션을 다른 경로로 재로드해 스킵 목록이 비워졌거나, 받기 싫은 카드를 한꺼번에 차단할 때 유용. 등록 직후 트리에서 해당 카드들이 자동으로 사라짐.

v0.4.45 (2026-05-21) — 일괄 다운로드 화면 전환 현상 수정

  • 일괄 다운로드 중 매 노트북마다 popup 창이 잠깐 떠오르며 화면이 전환되던 현상 수정 — Chrome 의 Windows 환경에서 chrome.windows.create({focused:false}) 가 더 이상 honor 되지 않게 거동이 바뀌어, 매 노트북마다 chrome.tabs.create({active:true}) 가 popup 창을 OS foreground 로 끌어올리던 문제. 단일 탭을 노트북 간에 재사용 (chrome.tabs.update 로 navigate) 하도록 구조 변경 — tabs.create 호출 자체가 세션 전체에서 0번. 화면 전환 빈도가 세션당 최대 1회 (첫 노트북 windows.create 시점) 로 감소.
  • debugger.attach 도 세션당 1회만 — 같은 탭을 재사용하므로 노란 디버그 배너 raise 도 1회만 발생.

v0.4.43 (2026-05-20) — 피드 순서로 보기 토글

  • 에피소드 목록 "피드 순서로 보기" 토글 — 현재 저장된 커스텀 피드 순서 그대로 에피소드 표를 확인하는 뷰 추가. 토글 ON 시 GitHub 의 podcast.json 에서 episodeOrder 배열을 읽어 그 순서로 정렬 (배열에 없는 파일은 날짜 내림차순으로 뒤에 배치). 그룹화·정렬·편집 모드 버튼은 보기 모드 중 비활성.

v0.4.42 (2026-05-20) — 다운로드 창 좌표 수정 + 피드 순서 편집

  • 일괄 다운로드 popup 창 좌표 수정 — Chrome 2026-05 업데이트로 windows.create / windows.update 에서 창 면적의 50% 이상이 화면 내에 있어야 한다는 조건이 추가됨. 기존 left:-32000, top:-32000 좌표가 에러로 차단되어 모든 일괄 다운로드가 "탭 열기 실패" 로 실패하던 문제 수정. left:-399, top:0, width:800, height:600 으로 변경 (화면 내 가시폭 401px = 50.1%). focused:false 와 visibilityState='visible' 는 그대로 유지.
  • 에피소드 RSS 피드 순서 편집 기능 — 관리 페이지 에피소드 목록에 [피드 순서 편집] 버튼 추가. 드래그&드롭 (☰ 핸들) 과 ▲▼ 버튼으로 에피소드 순서를 자유롭게 재배열. [피드에 적용] 클릭 시 docs/podcast.json 의 episodeOrder 배열로 저장되고 feed.xml 이 즉시 재빌드됨. [기본 순서로 초기화] 로 날짜 내림차순 복귀 가능.

v0.4.41 (2026-05-20) — 도움말 업데이트

  • 도움말 페이지에 §6-6 (피드 순서 편집), §6-7 (피드 순서로 보기) 추가. §3-3 다운로드 창 좌표 설명 갱신. §12 에 v0.4.42 테마 요약 추가.

v0.4.40 (2026-05-13) — 도움말 페이지 재구성

  • 도움말의 §12 버전별 업데이트를 테마 요약으로 압축 + 버전 단위 상세는 이 페이지 (changelog) 로 분기. 사용자가 도움말 페이지 한 화면에서 큰 흐름만 빠르게 훑고, 필요할 때 상세 페이지로 점프.

v0.4.39 (2026-05-13) — 다기기 스킵 누락 수정

  • 스킵한 카드가 다른 기기에서 다시 다운로드되던 race 수정 — 한 기기에서 음성개요를 스킵 → 다른 기기 스캔 시 그 카드의 artifact-labels DOM 이 늦게 렌더되면 shortId 가 빈 문자열로 들어와 스킵 필터가 우회되던 버그. (date, titleSlug) 폴백 매칭을 추가해 race 케이스도 정상 차단. 옵션 페이지 트리 UI 의 "스킵됨" 표시도 같이 정확해짐.

v0.4.38 (2026-05-13) — 일괄 스캔 가속

  • 직전 스캔 결과 자동 재사용 — 30분 안에 [모든 노트북 스캔] 을 또 누르면 풀 스캔 없이 곧바로 결과 표시. autoDownload 직후 한 번 더 확인하는 흐름의 대기시간을 0 에 가깝게. Shift+클릭으로 강제 풀 스캔.
  • 노트북별 변경 감지 캐시 — 홈 페이지의 노트북 카드에서 절대 시간 / 카운트 시그널을 추출해 "구조적 지문" 생성. 4시간 이내에 한 번 스캔된 노트북은 변동 없으면 탭 안 열고 캐시 그대로 사용. 새 음성개요 추가 등 변동 시엔 지문이 바뀌어 자동 풀 스캔.
  • graceful degrade — NotebookLM DOM 이 시그널을 노출 안 하면 매번 풀 스캔 (이전 동작과 동일). 추출률은 SW console 의 [scan:list] 로그에서 확인 가능.

v0.4.37 (2026-05-13) — 일괄 다운로드 안정화

  • UI freeze 해소 — 큰 카드 (40MB m4a) 다운로드 도중 popup / 옵션 페이지가 1~2초씩 멈추던 현상 제거. SW thread 의 동기 base64 인코딩을 offscreen document 로 완전히 이관.
  • 일괄 다운로드 popup 윈도우 숨김 — 다른 웹페이지 작업 중 NotebookLM popup 이 앞으로 튀어나오던 현상 회피. 화면 밖 좌표 (-32000, -32000) 로 띄움. 다운로드 동작은 동일.
  • 카드별 라이브 진행률 표시 — 진행 모니터의 현재 카드 영역에 stage (다운로드/MP3 변환/업로드) + byte 진행률 바. "다운로드 시작/끝" 만 보이던 옛 UI 보다 훨씬 자세한 활동 표시.
  • Stall 카드 빠른 회복 — 한 카드가 멈추면 10분 고정 timeout 대신 90초 idle (진행률 0건) 감지 후 다음 카드로 자동 이동. 정상 카드는 idle 안 걸림 — fetch chunk 마다 활성 신호 발생.

v0.4.36 (2026-05-12)

v0.4.35 (2026-05-12)

v0.4.34 (2026-05-11)

  • [한도 초과분 정리] 버튼 — 사용량 박스 (진행 모니터 + 에피소드 목록) 에서 retention 한도 초과 시 옛 파일을 익스텐션이 직접 ghDelete + 영구 스킵 등록. workflow 의 retention 컷과 같은 결과지만 스킵 목록에도 같이 등록돼 다음 스캔에서 신규 재인식 회피.
  • 다중선택 [선택 스킵] — 에피소드 목록 툴바에 [선택 삭제] 옆 파란 버튼 추가. 체크박스 다수 선택 후 한꺼번에 삭제 + 스킵 등록.

v0.4.33 (2026-05-10)

  • [스킵] = 삭제 + 영구 차단으로 통합 — [삭제] 는 단순 삭제 (다음 스캔에서 다시 받을 가능성 남김), [스킵] 은 삭제 + 영구 스킵 등록 (공간 확보 + 우후 차단) 으로 역할 명확 분리.
  • 스킵 목록에 메타 보관 — 등록 시 filename / title / 노트북명 / 날짜 / 등록 시각 함께 저장. [스킵 목록] 토글 패널에서 어떤 파일이었는지 사후 확인 가능.
  • 옛 v0.4.32 스킵 목록 (shortId 만) 자동 마이그레이션.

v0.4.32 (2026-05-10)

  • retention 영구 루프 회피 — bulk push → workflow 가 retention 으로 즉시 삭제 → 다음 스캔이 같은 카드를 신규로 재인식 → 무한 다운로드 사고의 구조적 해결.
  • 옛 카드 자동 스킵 (default 730일) — GitHub 연결 페이지에 일수 입력란. 노트북 생성일이 N일 이전인 카드는 일괄 다운로드에서 처음부터 스킵.
  • 저장소 사용량 박스 — 진행 모니터 + 에피소드 목록 양쪽에 사용량 / 한도 / % 진행바 (75% 노랑, 90% 빨강).
  • 스킵 목록 관리 — chrome.storage.sync 영구 보관 (다기기 공유). 에피소드 row 에 [스킵] 액션 + [스킵 목록] 토글로 개별 해제 / 전체 해제.

v0.4.31 (2026-05-10)

  • artifact-labels race fix — 스캔 시 NotebookLM 의 <span id="artifact-labels-{UUID}"> 가 늦게 렌더되어 dedup 키가 비어 같은 카드를 매번 신규로 잡던 사고. content.js scan 핸들러가 dedup 키 채워질 때까지 최대 3초 폴.
  • workflow push retry — 익스텐션 ghPut 와 workflow git push 가 race 날 때 origin/main 으로 reset + 재빌드 + push 재시도 (최대 3회 backoff).
  • 4-segment titleKey fallback — artifactId 가 race 로 빈 채 들어와도 (date, titleSlug, ext) 로 dedup 회복.
